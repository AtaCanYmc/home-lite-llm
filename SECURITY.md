## Security Architecture and Hardening Defaults

This repository implements defensive hardening controls across all services, scripts, and network bindings:

### 1. Master Key Protection and High Entropy
- The `MASTER_KEY` environment variable authenticates proxy API traffic and admin dashboard sessions.
- The onboarding wizard (`quickstart.sh`) generates a 256-bit cryptographically secure hex secret (32 random bytes) by default.

### 2. Virtual Key Hashing and Persistence
- LiteLLM proxy hashes virtual API keys using bcrypt before storing them in PostgreSQL (`STORE_MODEL_IN_DB=True`).
- Raw plaintext keys are only displayed once upon creation and are never logged or stored in cleartext.

### 3. Localhost-by-Default Network Isolation
- External port publications for LiteLLM (`4000`), Prometheus (`9090`), and Grafana (`3001`) bind to `127.0.0.1` by default (`${LITELLM_HOST:-127.0.0.1}`, etc.). This prevents unintentional exposure to local area networks or public interfaces on VPS deployments.
- The PostgreSQL database service (`db`) attaches exclusively to `litellm-network`. Database port `5432` is not published to any host interface.
- The ngrok traffic inspector UI binds strictly to `127.0.0.1:4040` in `docker-compose.ngrok.yml`.

### 4. Prompt and Payload Privacy (No Verbose Debug Logging)
- The `--detailed_debug` command flag is removed from production container definitions.
- User conversation messages, system prompts, completion tokens, and Authorization headers are not dumped into stdout or container log files on disk.

### 5. File System Permissions and Credential Protection
- Sensitive credential files (`.env`) are ignored in version control (`.gitignore`) and enforced with `0600` (owner read/write only) file modes.
- Database backup dumps generated by `scripts/backup_db.sh` enforce `umask 077` and `0600` permissions.
- Dynamic DNS updater scripts generated by `tunnels/port-forwarding/setup-ddns.sh` enforce `0700` permissions.

## Reporting a Vulnerability

If you discover a security vulnerability within this repository, report it responsibly.

1. **Do not open a public GitHub issue.** Public issues disclose vulnerabilities before patches are available.
2. Submit a private vulnerability report via [GitHub Security Advisories](https://github.com/AtaCanYmc/home-lite-llm/security/advisories/new).
3. If GitHub Advisories is inaccessible, send a private email to `security@atacanyilmaz.com` including:
   - Impact summary and affected configuration files.
   - Exact steps or minimal proof-of-concept commands to reproduce the issue.
   - Any proposed remediation or mitigation.
4. Maintainers acknowledge receipt of vulnerability reports within 48 hours and provide a status update with expected fix timelines.
